WebGPU で描いているので、WebGPU に対応したブラウザで動きます。対応していないブラウザでは、画面の中央に「このブラウザは WebGPU に対応していません」と出ます。スマホでは指で横になぞります。縦に動かし始めた指は、ページのスクロールになります。

The Nature of Code（Daniel Shiffman、2024 年版）の章の考え方を、自然の 1 場面にして WebGPU で動かすシリーズの 1 本で、この記事は 4 章「粒子系」を扱います。compute shader で 2 枚のバッファを交互につかい、固定の刻みで 1 歩ずつ進める組み立ては、シリーズで共通です。[イワシの群れの記事](https://webmanab.com/lab/boids-sardine-school-webgpu/)の「WebGPU で 1/60 秒ずつ進める」に書いています。

## 粒子系の考え方

4 章の粒子系（particle system）は、小さなものがたくさん生まれては消えていく様子を、1 つずつの粒と、粒の出入りを受け持つ側に分けて書く考え方です。

- 粒は、位置と速度を持ち、受けた力で動きながら年をとる。寿命が来たら、終わったことが外からわかる
- 粒を出す側（エミッター）は、どこから、いつ、いくつ出すかを決め、終わった粒を片づける
- 重力や風のように全体に掛かる力は、出す側がまとめて粒に渡す

粒 1 つの決まりは単純なままで、出す量と寿命を変えると、画面に見える粒の数や広がり方が変わります。

このデモでは、それぞれが次のものに当たります。

| 粒子系 | このデモ |
|---|---|
| 粒 | タンポポの種（72 本） |
| 出す側 | 綿毛の頭 |
| 出すきっかけ | なぞった息。カーソルが画面にないときは、ときどき 1 本ずつ（設定の「野原の風」を 0 にすると外れない） |
| 寿命 | 外れてから 17 秒。最後の 4 秒で薄くなって消える。頭を入れ替えるときは、それより早く消える |
| 粒に掛かる力 | 種のまわりの風との速度の差から出る空気抵抗と、重力 |

本の例では、出す側は粒を作り続けます。タンポポの頭には決まった数の種しかないので、このデモでは「粒を作る」かわりに「頭から外す」にして、残りが少なくなったら頭ごと入れ替えます。力も、頭からは渡しません。種がそれぞれ、じぶんの位置の風を読みます。

カーソルが画面にある間と、離れてから 4 秒間は、ひとりでに種を外しません。飛んでいる種を、どれもじぶんのなぞりで外したものにするためです。ひとりでに外れた種は、初めの画面で飛んでいる 4 本も、「終わった」になったものも、カーソルが入ると頭へ戻ります。

## しくみ

### 72 本の枠をつかい回す

本の例では、粒を配列に足し、終わった粒を配列から取り除きます。WebGPU では、compute shader が読み書きする storage buffer の大きさを作るときに決めます。粒が出入りするたびにバッファを作り直すことはせず、72 本分の枠をはじめに取っておいて、1 本ずつに次の状態を持たせます。

| 値 | 状態 |
|---|---|
| 0 | 頭に付いている |
| 1 | 飛んでいる |
| 2 | 終わった（描かない） |

状態は CPU と GPU の両方が持ちます。CPU は `Uint8Array` の `state` に持ち、何本飛んでいるかを数えます。GPU は種のデータの `vel.w` に同じ値を持ち、その値で動かすか、描くかを決めます。

CPU は、GPU が書いた状態を読み戻しません。読み戻すと、GPU の処理が終わって結果が届くまで待つことになるためです。かわりに、外した時刻に寿命を足した時刻（`expires`）を CPU で控えておき、毎フレーム比べます。`COUNT` は種の数の 72、`time` は固定の刻みで進めた時刻（秒）です。

```ts
// 飛んでいて、寿命の時刻を過ぎた種を「終わった」にする
for (let i = 0; i < COUNT; i++)
  if (state[i] === 1 && time >= expires[i]) state[i] = 2
```

GPU の側でも種ごとの年齢を数えて、寿命に届いたら `vel.w` を 2 にします（あとの「1 本ずつに力を掛ける」のコードの最後の行）。描くときは、年齢が 13 秒から 17 秒へ進む間、不透明度を下げ、`vel.w` が 2 の種は不透明度を 0 にします。

### なぞった線の近くから外す

頭から種を外す本数と、どの種を外すかは CPU で決めます。

1. `pointermove` のたびに、前の点からの速さを CSS px/秒で出す。毎秒 40px より遅い動きはつかわない
2. 速さを 600 で割った値（2.4 まで）に、設定の「息の強さ」を掛けて、息の勢いにする
3. 動いた距離と息の勢いに、なぞった線が頭に近いほど大きくなる重みを掛けて貯める。貯まった値の整数の部分を外す本数にして（1 回の移動で 5 本まで）、残りは次の移動に持ち越す。前の点から 0.2 秒以上あいたら、貯めた値を 0 に戻す
4. 頭に付いている種のうち、画面に映した位置となぞった線分との距離が 0.14（画面の高さを 2 とした長さ）以内のものを、距離が近い順で並べる
5. 飛んでいる種が 20 本を超えない分だけ、並べた順に外す

5 は次の関数です。`state` は上の状態の配列、`candidates` は 4 で並べた種の番号、`amount` は 3 で決めた本数、`maxFlying` は 20 です。

```ts
export const detachSeeds = (
  state: Uint8Array,
  candidates: number[],
  amount: number,
  maxFlying: number,
) => {
  // いま飛んでいる種を数える
  let active = 0
  for (const value of state) if (value === 1) active++
  // 付いている種から、決めた本数と上限までの空きの少ない方だけ前から取る
  const selected = candidates
    .filter((i) => state[i] === 0)
    .slice(0, Math.max(0, Math.min(amount, maxFlying - active)))
  for (const i of selected) state[i] = 1
  return selected
}
```

20 本が飛んでいるうちは、なぞっても種は外れません。寿命の来た種が「終わった」になると、その分だけまた外せるようになります。

外した種について GPU に書き込むのは、「外れた」という印です。位置や速度は書きません。種ごとに 8 個の数（付いている向きと寿命で 4 個、外れたかどうかで 4 個）を `rootsData` に並べ、同じ並びを storage buffer の `roots` に入れてあります。外したときは、外れたかどうかの 4 個だけを `roots` へ書き込みます。

`stroke` はなぞった線分で、ひとりでに外すときは値がありません。そのときの `candidates` は、なぞった線の近くではなく、頭に付いている種全部を、付いている向きと乱数で決めた順に並べたものです。

```ts
for (const i of detachSeeds(state, candidates, amount, MAX_FLYING)) {
  expires[i] = time + LIFETIME // 17 秒後に終わる
  automatic[i] = stroke ? 0 : 1 // なぞりで外したか、ひとりでに外れたか
  // 外れた印（4 個目の 1）を、その種の 16 バイトだけ GPU に書く
  rootsData.set([0, 0, 0, 1], i * 8 + 4)
  device.queue.writeBuffer(
    roots,
    i * 32 + 16,
    rootsData.subarray(i * 8 + 4, i * 8 + 8),
  )
}
```

`automatic` は、カーソルが入ったときに頭へ戻す種を見分けるのにつかいます。

### 1 本ずつに力を掛ける

種を動かすのは compute shader です。種 1 本を 1 つの呼び出しで受け持ちます。1 歩は 1/120 秒で、画面の 1 フレームで最大 8 歩進めます。

WGSL は TypeScript のテンプレート文字列で組み立てていて、`${FLIGHT.initial}` には 0.18、`${FLIGHT.seed}` には 0.24 が入ります。`s` はこの種のデータで、次の 4 つの `vec4f` を持ちます。

| | x, y, z | w |
|---|---|---|
| `pos` | 位置 | 年齢（秒） |
| `vel` | 速度 | 状態（0、1、2） |
| `axis` | 傘の向き | 軸のまわりの回転角 |
| `angular` | 傘の向きを変える回転の速さ | （つかわない） |

`r` は CPU が書いた `roots` のこの種の分で、`r.direction` の xyz に付いている向き、`r.direction.w` に寿命、`r.release.w` に外れた印が入っています。`air()` は、次の節の風の格子から、その位置の風の速度を補間して返します。`seedAir()` はその速度の長さを 0.20 まで、`limitedVelocity()` は渡した速度の長さを 2 つ目の値までに縮めます。`headPosition()` は頭の中心の位置で、頭の半径は 0.265 です。

まず、頭に付いている種の処理です。外れた印が立っていれば、ここで初速を決めて「飛んでいる」にします。カーソルが入ってひとりでに外れた種を頭へ戻すとき、CPU は外れた印を 0 に書き戻すだけです。最初の行で、その種の速度と状態を 0 にして「付いている」に戻します。

```wgsl
// 外れた印のない種は、速度と状態（vel.w）を 0 にする
if (r.release.w < 0.5) { s.vel = vec4f(0.0); }
if (s.vel.w < 0.5) { // 頭に付いている種
  // 頭の上の、付いている向きの位置に置く
  s.pos = vec4f(headPosition() + r.direction.xyz * 0.265, 0.0);
  s.axis = vec4f(r.direction.xyz, s.axis.w);
  if (r.release.w > 0.5) { // CPU が外れた印を書いた種
    // その場所の風の速度を初速にし、長さを 0.18 までにして「飛んでいる」にする
    s.vel = vec4f(limitedVelocity(seedAir(air(s.pos.xyz)), ${FLIGHT.initial}), 1.0);
    // 傘を上へ向けて離す
    s.axis = vec4f(normalize(vec3f(r.direction.x * 0.3, 1.0, r.direction.z * 0.3)), s.axis.w);
    s.angular = vec4f(0.0);
  }
}
```

位置を置き直すときに年齢（`pos.w`）を 0 にしているので、外れた種の年齢は 0 から数えます。

次が、飛んでいる種の処理です。

```wgsl
if (s.vel.w > 0.5 && s.vel.w < 1.5) { // 飛んでいる種だけ
  let dt = u.dt; // 1/120 秒
  // …（傘の向きの個体差に使う乱数。下の省いた部分で使う）
  // 種のまわりの風と、種の速度との差
  let relative = seedAir(air(s.pos.xyz)) - s.vel.xyz;
  // 差を、傘の軸に沿った向きと、それ以外の向きに分ける
  let axial = s.axis.xyz * dot(relative, s.axis.xyz);
  // 傘の軸に沿った向きの抵抗を強くする
  let force = (relative - axial) * 1.8 + axial * 4.6;
  // 抵抗と重力で速度を変え、長さを 0.24 までにする
  s.vel = vec4f(limitedVelocity(s.vel.xyz + (force + vec3f(0.0, -0.22, 0.0)) * dt, ${FLIGHT.seed}), 1.0);
  // 速度で位置を進め、年齢（pos.w）を足す
  s.pos = vec4f(s.pos.xyz + s.vel.xyz * dt, s.pos.w + dt);
  // …（傘を上へ戻す回転と、軸のまわりの回転）
  // 年齢が寿命（17 秒）に届いたら「終わった」にする
  if (s.pos.w >= r.direction.w) { s.vel.w = 2.0; }
}
```

力で速度を変え、速度で位置を進める並びは、The Nature of Code の 1 章と 2 章の書き方と同じです。重さはつかっていないので、力をそのまま加速度として足しています。

空気抵抗は、風と種の速度の差に比例させています。傘の軸に沿った向きの係数（4.6）を、横の係数（1.8）より大きくしているので、傘を上にした種は上下の動きを強く抑えられて、ゆっくり沈みます。横の係数は小さいので、風が変わったとき、横の速さはすこし遅れて風に追いつきます。

### 風は格子の流体から取る

なぞった息は、種に直接は足していません。空間を 40×24×12 のセルに分けて風の速度を持たせ、息はその風に入れます。種は前の節の `air()` で、じぶんの位置の風を読みます。

風は、画面の 1 フレームごとに、そのフレームで進めた時間の分だけ、次の順で compute shader を回して進めます。

1. 各セルの速度を、流れを逆にたどった先の速度で置き換える（移流）。息をやめても、吹いた流れが運ばれて残る。同じ shader で、カーソルのまわりの速度をなぞった向きの速度へ近づける。カーソルから離れるほど弱める。ひとりでに種を外すのと同じ間（カーソルが画面になく、離れて 4 秒たったあと）は、かわりに野原の弱い風を足す
2. セルごとに、流れ込む量と流れ出る量の差を出す
3. その差をもとに、ヤコビ法を 36 回くり返して圧力を求める
4. 圧力の差の分だけ速度を引いて、流れ込む量と流れ出る量の差を減らす

息は風の格子に入るので、すでに飛んでいる種のそばをなぞると、その種の流れる向きも変わります。2〜4 で、息で押した空気がまわりへ回り込むので、なぞった線から離れた種も動きます。

風を時刻と位置の式だけで書く方法は採っていません。式で書いた風に息を足しても、吹いた流れが運ばれて残ったり、まわりへ回り込んだりはしないためです。

息の速さをそのまま風に入れると、外れた種はすぐに画面の外へ出てしまいます。そこで、なぞる速さ（CSS px/秒）を 4800 で割って息で入れる速度にしています。外れたときの初速だけを抑えても、風に押されてまた速くなるので、息で入れる速度（0.60）、外れたときの初速（0.18）、種が受け取る風の速度（0.20）、種の速度（0.24）のそれぞれに上限を置いています。どれも速度の各成分ではなく長さを縮めるので、流れる向きは変わりません。

### 頭ごと入れ替える

頭に付いている種が 18 本（72 本の 4 分の 1）以下になると、2.5 秒待ってから、古い茎が 2 秒で下がって消え、あたらしい頭が 3.5 秒で下から出てきます。茎が下がる間は、飛んでいる種も古い頭といっしょに薄くなります。古い頭が消えたところで、飛んでいる種も終わった種も含めて 72 本の状態を全部「付いている」に戻し、風の速度も 0 にします。待っている間と入れ替えの間は、なぞっても種を外しません。

待っている 2.5 秒の間に、カーソルが入ってひとりでに外れた種が頭へ戻り、付いている種が 18 本を超えたときは、入れ替えを取りやめます。
