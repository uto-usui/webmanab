雪の積もった松の枝を、下へ引いて離します。小さく引くと、雪は載ったまま枝と一緒に下がり、離しても落ちません。速く強く引くと、引いている途中で雪が枝から浮き、離すと跳ね返った枝に下から突き上げられて、塊ごとに回りながら落ちていきます。雪が全部落ちると、しばらくして積もり直します。

## 6 章の考え方

1〜5 章では、力を求め、加速度で速度を、速度で位置を進める手順をじぶんで書いてきました。6 章は、その手順を物理ライブラリに任せる章です。任せると、作る側は動かしたいものを最初にライブラリへ登録し、毎フレーム受け取った位置で描けばよくなります。動かす計算はライブラリの中で進みます。

ライブラリの中の世界は、おおまかに次のものでできています。

1. 物体: 世界の中を動く 1 つ 1 つのもの。箱や円のような形を持つ
2. つなぎ: 2 つの物体を結ぶもの。決まった長さを保つつなぎは、硬さを下げるとばねに近づく。マウスで物体を動かすときも、物体の位置を直接書き換えずに、マウスの位置へ物体を引くつなぎを張る
3. 衝突: 2 つの形が重なっているかを調べること（検出）と、当たったあとの速度を決めること（応答）に分かれる。形が複雑になるほどじぶんで書くのが大変になり、6 章は、ライブラリをつかう理由としてここを挙げている
4. 粒子をばねでつなぐと、紐や布のように形の変わる物体になる
5. 位置を 1 刻みずつ進める計算（積分）にはいくつかの方法があり、ライブラリによってつかう方法が違う

このデモでは物理ライブラリをつかわず、これらを TypeScript で組んでいます。デモの中での置き換えは次のとおりです。

| 6 章に出てくるもの | デモでの置き換え |
|---|---|
| 物体 | 雪の塊。重心、速度、回転の速さ、向き、質量を持つ。表示する幅が 600px 以上で 12 個、未満で 8 個 |
| 世界を 1 刻み進める | `BoughPhysics` の `step()`。1/120 秒ずつ進める |
| つなぎ | 枝の区間どうし（曲げとねじれのばね）、枝に載っている雪と枝の面、隣り合う雪の塊どうし |
| マウスで引くつなぎ | つかんだ点を指の位置へ引くばね |
| 衝突の検出と応答 | 枝から外れた雪と、枝・松葉。雪の塊どうしは当てていない |
| 粒子をばねでつないだ柔らかい物体 | 枝。粒子とばねの代わりに、区間ごとの回転とばねで組む |
| 積分の方法 | 枝は陰的な更新、落ちる雪は速度を先に更新してから位置を進める形 |
| 物の位置を受け取って描く | 物理の結果を storage buffer に書き、WebGPU のシェーダーが読んで描く |

このデモで足したのは、つなぎが切れることです。枝に載っている雪は、支えきれない力がしばらく続くと枝から外れ、そこから先は衝突で枝とやりとりする物体になります。

## しくみ

### 枝: 区間ごとの回転を根元から重ねる

枝は、主枝の 12 点と、2 本の小枝の 7 点ずつを合わせた 26 点でできています。小枝の付け根は主枝の点を共有しています。表示する幅が 600px 未満のときは、主枝を短くして小枝を 1 本にした 19 点です。

点どうしを長さを保つつなぎで結ぶと、つなぎを毎刻み満たすように位置を直す計算が要ります。このデモは、点の位置を自由に動かす代わりに、区間ごとに「親の区間からどれだけ回っているか」を 3 つの数（回転ベクトル）で持ちます。3 つは、区間の軸まわりのねじれと、2 方向の曲げにあたります。点の位置は、根元から順に回転を重ねて求めます。区間の長さは計算のどこでも変わらないので、長さを保つ処理は要りません。

次のコードの `this.q` は、区間ごとに 3 つずつ並べた回転ベクトルです。`edges` の各区間は、両端の点の番号 `a` と `b`、親の区間の番号 `parent`（根元の区間は -1）、長さ `length` を持ちます。`frames[i]` は区間 `i` の向きを表す 3 本の軸で、順に接線、断面の上、断面の左右です。`positions` は点の位置、`root` は根元の点の位置、`restFrame` は区間の休止時の向き、`relative` は休止時の親の区間との相対の向きです。

```ts
update() {
  // 根元の点は動かさない
  this.positions[0] = this.root.slice()
  this.edges.forEach((edge, i) => {
    // 親の区間の向きに、休止時の親との相対の向きを重ねる（根元の区間は休止時の向き）
    const parent = edge.parent < 0 ? edge.restFrame : this.frames[edge.parent]
    const base = product(parent, edge.relative)
    // この区間の回転ベクトルを回転行列にして重ねる
    const q = Array.from(this.q.slice(i * 3, i * 3 + 3))
    this.frames[i] = product(base, rotation(q))
    // 回転ベクトルの変化と、点の動きを結ぶ軸（点の速さと、枝の方程式の計算に使う）
    this.axes[i] = product(base, rotationJacobian(q))
    // 根元からこの区間までに通る区間の番号
    this.chains[i] = [...(edge.parent < 0 ? [] : this.chains[edge.parent]), i]
    // 区間の先の点は、根元側の点から接線の向きへ区間の長さだけ進めた位置
    this.positions[edge.b] = add(
      this.positions[edge.a],
      mul(this.frames[i][0], edge.length),
    )
  })
}
```

区間どうしのつなぎは、回転ベクトルを 0 に戻そうとするばねです。ばねの硬さは、丸い棒の曲げとねじれの式から、枝の半径の 4 乗に比例させています。半径は根元から先へ細くなるので、先へいくほど柔らかくしなります。

| | 硬さ |
|---|---|
| 曲げ | `E × π × 半径⁴ / 4` |
| ねじれ | `G × π × 半径⁴ / 2`、`G = E / 2.6` |

これを隣り合う区間の長さの平均で割った値を、回転ベクトルにかかるばねの硬さにしています。

`E` は表示する幅が 600px 以上で 1.8×10⁷、未満で 1.25×10⁷ です。場面の大きさに合わせて決めた値で、本物の松の値ではありません。

1 刻みごとの速さの更新では、ばねの力を刻みの終わりの姿勢で見積もる形（陰的な更新）にして、連立方程式を Cholesky 分解で解いています。枝に載っている雪の重さと、つかんでいる点のばねも、同じ方程式に入れます。雪の重さで枝がたわみ、雪が外れて軽くなると枝が戻るのは、この方程式に雪の質量が入っているためです。

### 載っている雪: 支えきれない力が続いた分をためる

枝に載っている雪の塊は、枝の断面の上に置いた面（支持面）に下面を合わせ、面と一緒に動きます。面から雪を離す向きの動きは止めておき、面に沿って滑る動きだけを残します。

雪が枝に留まるかどうかは、支持面から見た重力で決めます。面が下へ加速すると、面の上の雪にかかる重力はそのぶん小さく見え、面が重力より速く下へ加速すると、雪を面から持ち上げる向きになります。その力を面の向きに分けて、次の 3 つにします。

| 力 | 意味 |
|---|---|
| `normal` | 面へ押しつける力 |
| `shear` | 面に沿う力 |
| `lift` | 面から離す力 |

面に沿う力のうち静止摩擦で支えきれない分と、面から離す力を足したものが、雪の付着に求められる力です。それが付着で耐えられる力（接触面積に比例）を超えた割合を、刻みごとに足してためていきます。

次のコードは `step()` の中で、雪の塊 1 つずつに動く部分です。`c` は塊の状態、`s` は塊の大きさや形の乱数の種、`basis` は塊が載っている枝の区間の 3 本の軸、`gravity` は `[0, -2.8, 0]`、`dt` は 1/120 秒です。`acceleration` は、支持面の位置の変化から求めた、この刻みの支持面の加速度です。`u.adhesion` は設定の「雪の留まりやすさ」、`u.settling` は開いた直後や雪を載せ直したときに、6 秒ぶん形をならしている間だけ 1 になる値です。`c.growth` は積もり具合（0〜1）、`c.local` は支持面に沿って滑ったずれ、`i` は塊の番号です。

```ts
if (c.attached) {
  // 支持面の加速度を、45 ミリ秒の時定数でならす
  c.supportAcceleration = add(
    mul(c.supportAcceleration, Math.exp(-dt / 0.045)),
    mul(acceleration, 1 - Math.exp(-dt / 0.045)),
  )
  // 支持面から見た重力を、面の軸ごとの成分にする
  const effective = apply(
    transpose(basis),
    sub(gravity, c.supportAcceleration),
  )
  const normal = Math.max(0, -effective[1]) * c.mass // 面へ押しつける力
  const shear = c.mass * Math.hypot(effective[0], effective[2]) // 面に沿う力
  const lift = c.mass * Math.max(0, effective[1]) // 面から離す力
  // 付着で耐えられる力。接触面積に、塊ごとに 0.21〜0.31 の係数と留まりやすさを掛ける
  const area = 4 * s.size[0] * Math.min(0.26, s.size[2]) * c.growth
  const capacity =
    area * (0.21 + 0.1 * Math.sin(s.phase * 2.71 + 1) ** 2) * u.adhesion
  // 静止摩擦の係数。塊ごとに 38〜43° の角度の tan
  const friction = Math.tan(
    ((38 + 5 * Math.sin(s.phase * 1.7) ** 2) * Math.PI) / 180,
  )
  // 摩擦で支えきれない分と、面から離す力を足す
  const demand = lift + Math.max(0, shear - friction * normal)
  const overload = Math.max(0, demand / Math.max(0.00001, capacity) - 1)
  // 超えた割合を 3 で頭打ちにして足す。超えていない間は毎秒 0.3 ずつ減らす
  c.damage = Math.max(
    0,
    c.damage + dt * (Math.min(3, overload) - (overload === 0 ? 0.3 : 0)),
  )
  // …（面に沿って滑らせ、支持面と一緒に位置と向きを動かし、その差から速さと回転の速さを求める処理）
  // ためた値が 0.1 を超えるか、面に沿って滑りすぎたら外す
  if (
    !u.settling &&
    c.growth > 0.15 &&
    (c.damage > 0.1 ||
      Math.abs(c.local[2]) > 0.32 ||
      Math.abs(c.local[0]) > s.size[0] * 0.8)
  )
    this.release(i)
}
```

付着に求められる力が耐えられる力の 2 倍なら、0.1 秒続くと外れます。3 倍なら約 0.05 秒、4 倍以上は頭打ちになって約 0.03 秒です。

デモでの動きと照らし合わせると、次のようになります。

- ゆっくり引くと、支持面の加速度が小さいので `lift` が出ず、雪は載ったまま下がる
- 速く引くと、支持面が重力より速く下へ加速して `lift` が出て、雪が外れて空中に残る
- 跳ね返った枝が上で急に向きを変えると、同じように `lift` が出て、雪は上向きの速さを持ったまま外れる
- 枝が大きく傾くと、`shear` が摩擦を超えて雪が滑り、滑りすぎると外れる

塊の質量（厚みの違い）、耐えられる力の係数、摩擦の角度が塊ごとにすこしずつ違うので、同じ枝の雪でも一度には外れません。支持面の加速度をならしているのは、ポインターの入力が飛び飛びに届いて加速度が急に跳ねても、それだけで雪が外れないようにするためです。

### 滑る雪と、隣の塊とのつなぎ

面に沿う動きは、静止摩擦と動摩擦で分けています。面に沿う速さがほとんど 0（0.002 未満）で、面に沿う力が「摩擦の係数 × 押しつける力 + 耐えられる力」以下なら、止めたままにします。そうでなければ、面に沿う力で加速させてから、速さを減らします。1 秒あたりに減らす速さは、「0.58 × 押しつける力 + 耐えられる力 × 0.35」を質量で割った値です。

1 本の枝の雪は 4 つの塊に分けてあり、隣どうしの塊は境目のつなぎで結ばれています。このつなぎは、2 つの塊の滑ったずれの差をすこしずつそろえます。ずれの差が約 0.059（0.045 の 1.3 倍）を超えた状態が続くか、どちらかの塊が外れると切れて、その後はつなぎ直しません。

### 外れる: 支持面とのつなぎを外す

`release()` は、塊の `attached` を `false` にして、隣の塊とのつなぎも切ります。速さは変えません。載っている間も、塊の速さと回転の速さは支持面の動きから毎刻み求めているので、外れた塊は、その瞬間の枝の速さをそのまま持って飛んでいきます。

### 落ちる雪と枝の衝突

外れた塊は、重力と空気の抵抗で落ちます。抵抗は速さの 2 乗に比例し、進む向きから見た塊の断面積が大きいほど、質量が小さいほど強くかかります。回転の速さもすこしずつ落とします。

落ちる途中の塊は、すべての枝と松葉に当たります。速い枝が雪をすり抜けないよう、1 刻み（1/120 秒）を 4〜64 の小刻みに分け、1 つの小刻みで、塊も枝も松葉も 0.018 より大きく動かず、塊が 0.05 ラジアンより大きく回らないようにしています（64 で頭打ち）。枝と松葉の位置も、刻みの前後の間を小刻みごとに補間します。雪の塊どうしの当たりは調べていません。

衝突は、6 章の言い方に合わせると、次の 2 段に分かれます。

| 段 | このデモでのやり方 |
|---|---|
| 検出 | 枝を半径付きの線分、松葉 1 本をたわみに沿って 2 つに折った細い線分で表し、雪の塊を塊と一緒に回る箱で表す。線分と箱の最も近い距離から、めり込みの深さと向きを求める |
| 応答 | いちばん深い当たりから順に、めり込みを押し戻し、近づく向きの速さを打ち消してすこし跳ね返す衝撃を与える。1 つの小刻みで 8 回まで繰り返す |

衝撃の大きさは、雪の質量と回転のしにくさに加えて、当たった点での枝の動きやすさから求めます。枝の動きやすさは、枝と、枝に載っている雪の質量、減衰、ばね、つかんでいる点のばねから計算します。跳ね返りの係数は枝で 0.12、松葉で 0.02、摩擦は枝で衝撃の 0.45 倍、松葉で 0.65 倍までです。雪に与えた衝撃と逆向きの衝撃は枝の速さに足し、枝の位置は次の刻みで動きます。

当たり判定につかう箱は、見た目の雪の形とは別に持っています。見た目の細かいでこぼこは、当たり判定と質量のどちらにも入れていません。

落ちる塊は、時間とともに角から削れて質量が減ります。削れた分は塊と同じ速さで離れていく扱いにしているので、残った塊の速さは変わりません。塊が画面の下へ出ると、計算を止めます。

### つかむ: 指と枝の間のばね

枝の描かれた線から 24px 以内か、枝に載っている雪の上を押すと、枝をつかめます。つかんだ点は、6 章のマウスで引くつなぎと同じく、位置を直接書き換えずにばねで指の位置へ引いています。ばねの硬さは 95 で、枝の陰的な更新の方程式に入れます。指を遠くまで動かしても、つかんだ点を引く目標は、つかみ始めた位置から場面の単位で 2.8 までに抑えています。

### 積もり直す

全部の塊が画面の下へ出て止まり、枝をつかんでいなければ、4 秒待ってから積もり直します。あたらしい雪は 3.5 秒かけて小さな形から厚くなり、雪の体積に合わせて枝にかかる重さも増えていきます。枝の姿勢は元に戻さないので、軽くなって跳ね上がった枝が、積もる雪の重さですこしずつ下がります。

### CPU で解いて、WebGPU で描く

物理はすべて CPU の TypeScript で解いています。Node で物理を確かめるテストと画面とで、同じ実装をつかうためです。GPU の compute シェーダーはつかっていません。

1 フレームごとに、経過時間に応じた刻み数だけ `step()` を進め（1 フレームに 4 刻みまで）、枝の点と雪の塊の姿勢を storage buffer に書きます。雪の塊は 1 つ 192 バイトで、今の刻みの位置と 3 本の軸に加えて、1 つ前の刻みの位置と軸も持たせています。

物理は 1/120 秒ずつしか進まないので、画面の更新がその途中に来ると、そのままでは動きが段になります。そこで、まだ進めていない端数の時間を 1 刻みに対する割合（`u.interpolation`）にして、シェーダーで前の刻みと今の刻みの間を補間します。

```wgsl
// 塊の位置を、前の刻みと今の刻みの間で補間する
fn snowOrigin(s: Snow) -> vec3f { return mix(s.oldOrigin.xyz,s.origin.xyz,u.interpolation); }
// 2 本の軸を補間して直交をなおし、3 本目は外積で作る
fn snowBasis(s: Snow) -> mat3x3f {
  let x=normalize(mix(s.oldX.xyz,s.axisX.xyz,u.interpolation));
  let y0=mix(s.oldY.xyz,s.axisY.xyz,u.interpolation);
  let y=normalize(y0-x*dot(x,y0));
  return mat3x3f(x,y,normalize(cross(x,y)));
}
```

枝の点も同じように前の位置を持ち、頂点シェーダーで補間します。枝は頂点バッファを持たず、頂点シェーダーが区間の番号と頂点の番号から、両端の点のあいだを曲線でつないだ管の頂点（断面 12 分割、区間の長さ方向 4 分割）を作ります。

雪は、塊ごとに画面上の四角を 1 枚だけ描き、フラグメントシェーダーで距離場をたどって（レイマーチ、最大 72 歩）表面を探します。距離場は、つぶれた楕円体 7 つをなめらかにつないだ形にノイズを重ねたものです。1 本の枝の 4 つの塊は同じ楕円体の並びを読むので、載っている間は 1 つの帯に見えます。表面が見つかった点の深度を `@builtin(frag_depth)` で書き出すので、四角 1 枚でも、枝や松葉との前後は深度テストで正しく決まります。影の深度を描くときも、同じ距離場をつかっています。
