## 2 章「力」の考え方

### 力を足し合わせて、質量で割る

1 章では、位置に速度を足し、速度に加速度を足して物を動かしました。2 章は、その加速度がどこから来るかの話です。物に掛かる力を全部足し合わせ、物の質量で割ったものが加速度になります。重いものほど、同じ力で動きにくくなります。

力は毎フレーム足し直します。重力、風、摩擦のように力がいくつあっても、加速度を決めるのは、足し合わせた結果です。

### 引き合う力と、近すぎるとき

二つのものが引き合う重力は、二つの質量の積に比例し、距離の 2 乗に反比例します。向きは相手のいるほうです。距離が半分になれば、力は 4 倍になります。

この式は、距離が 0 に近づくと力がいくらでも大きくなります。画面の中で 2 つの点がほぼ重なると、その 1 フレームで大きな速度がつき、点が画面の外へ飛んでいきます。本では、力の計算につかう距離を一定の範囲に収めてこれを防いでいます。

このデモでは範囲を決めず、距離の 2 乗へ小さな値（軟化長の 2 乗）を足してから割ります。これを軟化と呼びます。1 つの相手から受ける加速度は次のとおりです。

```
加速度 = 相手の質量 × d / (|d|² + ε²)^(3/2)
```

`d` は相手へむかうベクトル、`ε` は軟化長で、デモでは 0.22 にしています。`d` を `|d|³` で割った値は、向きが相手のほう、大きさが距離の 2 乗に反比例します。`|d|³` は `(|d|²)^(3/2)` なので、軟化ではこの `|d|²` に `ε²` を足します。距離が軟化長より十分に大きいところでは、ふつうの逆 2 乗とほぼ同じ力になります。近いところでは、力が一定の大きさを超えなくなります。

距離に上限も付けると、上限より遠いところでは、近い側と遠い側の力が同じになります。軟化は近いところの力だけを変えるので、離れたところでは距離による力の差が残ります。この差が、あとで書く尾のもとです。

### みんながみんなを引く

本の章の終わりでは、どの物体も、ほかのすべての物体に引かれる形（n 体）へ広げています。物体ごとに、ほかの全部の相手からの力を足し合わせます。

このデモの質量点は 2,048 個で、質量点どうしだけで 1 歩ごとに 2,048 × 2,048、約 420 万組の力を計算します。光の頂点（後で書きます）も合わせると、光の頂点が 32,768 個のときで約 7,100 万組になり、これを毎秒 120 歩を目標に進めるので、GPU で並列に計算します。

### 同じ相手でも、場所で力が違う

銀河の円盤のうち、相手の銀河に近い側は強く、遠い側は弱く引かれます。たとえば、相手の芯（銀河の中心の明るいところ）から 4 離れたところにある半径 2 の円盤なら、近い端は距離 2、遠い端は距離 6 にあり、逆 2 乗では力が 9 倍違います。

芯は円盤の平均的な力で動くので、近い側は芯より強く引かれて相手のほうへ、遠い側は芯より弱く引かれて取り残されます。円盤は相手と結ぶ向きに引き伸ばされ、外側の星が円盤からはがれていきます。これが潮汐で、デモの尾はこの差から出ています。尾の形を描く処理はありません。

## しくみ

### 質量点と光の頂点

デモの中で動くものは 2 種類あります。

| | 数 | 何をするか |
| --- | --- | --- |
| 質量点 | 2,048（1 つの銀河に 1,024） | 互いに引き合う。重力の源になる |
| 光の頂点 | 32,768（タッチの端末や小さい画面では 16,384） | 質量点に引かれて動く。ほかを引かない。円盤の面の頂点になる |

1 つの銀河の質量点は、平たい円盤の 256 個と、芯のまわりを球状に囲む 768 個です。銀河の質量は、円盤が 10%、球状のほうが 90% です。球状のほうも固定した中心にせず、一つずつ軌道を持って動きます。小さいほうの銀河は、大きいほうに対して大きさ 0.78 倍、質量 0.65 倍です。

重力の源は質量点だけです。光の頂点まで源に入れると、組の数は 3 万 × 3 万を超えます。

2 章の考え方では、加速度は力をじぶんの質量で割ったものでした。重力はじぶんの質量に比例するので、割るとじぶんの質量は消えます。そのため、加速度の式に出てくるのは相手の質量だけで、質量を持たない光の頂点も、質量点と同じ式で動かせます。

### 全部の相手からの重力を足す

重力の計算は WGSL の compute シェーダーです。1 つのスレッドが、1 つの点（質量点か光の頂点）の加速度を求めます。

次の `acceleration` は、`i` 番の点が受ける加速度を、すべての質量点から足し合わせます。`before` は力を受ける側の点の配列、`sources` は重力の源の質量点の配列で、どちらも `p.xyz` が位置、`p.w` が質量です。`sim.masses` は質量点の数（2,048）、`sim.softening2` は軟化長の 2 乗です。`local` は、64 スレッドで 1 組の workgroup の中での番号です。

```wgsl
// workgroup の 64 スレッドで共有するメモリ
var<workgroup> tile: array<vec4f, 64>;

fn acceleration(i: u32, local: u32) -> vec3f {
  let p = before[i].p.xyz;
  var a = vec3f(0.0);
  // 質量点を 64 個ずつ区切って読む
  for (var base = 0u; base < sim.masses; base += 64u) {
    // 64 スレッドが 1 個ずつ共有メモリへ読み込む
    tile[local] = sources[base + local].p;
    // 64 個がそろうまで待つ
    workgroupBarrier();
    for (var j = 0u; j < 64u; j++) {
      // 相手へ向かうベクトル
      let d = tile[j].xyz - p;
      // 1 / √(距離² + 軟化長²)
      let inv = inverseSqrt(dot(d, d) + sim.softening2);
      // 相手の質量 × d / (距離² + 軟化長²)^(3/2) を足す
      a += d * (tile[j].w * inv * inv * inv);
    }
    // 全員が使い終わるまで待ってから、次の 64 個で上書きする
    workgroupBarrier();
  }
  return a;
}
```

各スレッドが 2,048 個の質量点を毎回 storage バッファから読むと、同じ値を 64 スレッドが別々に読みます。64 個ずつ共有メモリに読み、workgroup の中でつかい回すと、storage バッファから読む回数が 64 分の 1 になります。

本では、じぶんとの組を飛ばしていました。このデモの質量点は `sources` にじぶんも入っていますが、分岐はありません。じぶんとの組では `d` が 0 なので、足す値も 0 になります。軟化長があるので、0 で割ることもありません。

### 1 歩進める

更新の順番は本と同じで、速度に加速度を足してから、あたらしい速度で位置を進めます。違いは 3 つです。

- 1 フレームを 1 歩とせず、実時間の 1/120 秒ごとに 1 歩進める。120Hz の画面でも 60Hz の画面でも、1 秒に進む量が同じになる。1 フレームに進める歩数は 3 歩まで
- 最初の 1 回だけ、速度を半歩ぶん戻しておく
- 重力のほかに、銀河ごとの速度の補正（`bulkMotion`）を速度に足す。中身は「つかんで投げる」で書く

`sim.dt` は 1 歩で進める物理時間（0.0125）です。実時間の 1/120 秒で物理時間が 0.0125 進むので、物理時間は実時間の 1.5 倍の速さで進みます。`before` から読んで `after` へ書きます。

```wgsl
// 最初の 1 回だけ。速度を半歩ぶん戻す
@compute @workgroup_size(64) fn initialize(
  @builtin(global_invocation_id) id: vec3u, @builtin(local_invocation_id) lid: vec3u) {
  let a = acceleration(id.x, lid.x);
  var b = before[id.x];
  b.v = vec4f(b.v.xyz - a * sim.dt * 0.5, b.v.w);
  after[id.x] = b;
}

// 毎歩。速度を進めてから、その速度で位置を進める
@compute @workgroup_size(64) fn advance(
  @builtin(global_invocation_id) id: vec3u, @builtin(local_invocation_id) lid: vec3u) {
  var a = acceleration(id.x, lid.x);
  // 配列の前半が大きい銀河、後半が小さい銀河
  let galaxy = select(0u, 1u, id.x >= arrayLength(&before) / 2u);
  var b = before[id.x];
  // bulkMotion は銀河ごとの速度の補正（つかむ操作と、画面に収めるための減速と引き戻し）
  b.v = vec4f(b.v.xyz + a * sim.dt + bulkMotion[galaxy].xyz, b.v.w);
  b.p = vec4f(b.p.xyz + b.v.xyz * sim.dt, b.p.w);
  after[id.x] = b;
}
```

速度を半歩戻しておくと、位置は 0, 1, 2, … 歩目の値、速度は 0.5, 1.5, … 歩目の値として交互に進みます。位置と速度を半歩ずらして交互に進めるこのやり方を、leapfrog と呼びます。

この 2 つの関数を、光の頂点と質量点のそれぞれにつかいます。次は 1 フレームで `n` 歩進めるところです。`initialize` は最初の 1 回だけ `true`、`count` は光の頂点の数です。`mass` と `light` は、読む側と書く側の 2 枚のバッファを交互につかう入れ物で、`index` が今読んでいる側の番号（0 か 1）、`flip()` が入れ替える関数です。`initP` と `stepP` は `initialize` と `advance` のパイプライン、`initGroups` と `stepGroups` はその bind group を読む側の番号ごとに 2 組ずつ用意したもの、`followP` と `followGroups` は速度の補正を求めるパイプラインと bind group、`MASS_COUNT` は質量点の数（2,048）です。

```ts
const pass = encoder.beginComputePass({ label: 'galaxy gravity' })
for (let i = 0; i < n; i++) {
  if (!initialize) {
    // 銀河ごとの速度の補正を求めて bulkMotion に書く（2 つの銀河で 2 スレッド）
    pass.setPipeline(followP)
    pass.setBindGroup(0, followGroups[light.index])
    pass.dispatchWorkgroups(2)
  }
  pass.setPipeline(initialize ? initP : stepP)
  const group = (initialize ? initGroups : stepGroups)[mass.index]
  // 光の頂点を、質量点の重力で進める
  pass.setBindGroup(0, group.light)
  pass.dispatchWorkgroups(count / 64)
  // 質量点を、質量点の重力で進める
  pass.setBindGroup(0, group.mass)
  pass.dispatchWorkgroups(MASS_COUNT / 64)
  // 両方を進めてから入れ替える。光の頂点も質量点も、更新前の質量点を読む
  mass.flip()
  light.flip()
}
pass.end()
```

`group.light` は、重力の源に質量点のバッファ、力を受ける側に光の頂点のバッファを結びます。`group.mass` は、源も受ける側も質量点のバッファです。光の頂点はどちらの組でも源に入らないので、引かれるだけで、ほかを引きません。

入れ替え（`flip()`）を、光の頂点と質量点の両方を進めたあとに置いているのは、2 つが同じ更新前の質量点を読むようにするためです。質量点を進めたところで入れ替えると、光の頂点だけが 1 歩先の質量点の重力を読みます。

### 円盤をまわしておく

止まった円盤を置くと、円盤は芯へ落ちてつぶれます。円盤がつぶれずにまわり続けるには、それぞれの点が、そこで受ける内向きの力とつり合う速さで円を描いている必要があります。半径 `r` で内向きの加速度が `a` のとき、円を描く速さは `√(a × r)` です。

光の頂点の初速は、半径ごとにこの速さを求めて与えています。その半径の円の上の 24 方向で、1 つの銀河の質量点から受ける軟化した重力を求め、内向きの成分を平均します。点ごとに近くの質量点の偏りを拾うと、円盤の中で速さがばらつくので、半径ごとの平均にしています。

質量点も、それぞれが受ける内向きの力から同じように円の速さを求めます。円盤の質量点は円盤の面の中で、球状の質量点はばらばらの向きの軸のまわりでまわします。

### 円盤を面で描く

光の頂点は、銀河ごとに角度 128 分割、半径 128 分割（タッチの端末や小さい画面では 64 分割）の格子に並べ、隣どうしを三角形で結んでいます。点を 1 つずつ描くと、引き伸ばされたところで点の間がすき、尾が粒の列になります。面にしておけば、伸びたところも連続した膜として描けます。

| 面の扱い | 計算 |
| --- | --- |
| 模様 | 最初の円盤の座標で、腕と塵の帯を描く。模様は面と一緒に運ばれる。腕は描いた模様で、重力から生まれる渦状腕の計算はしていない |
| 明るさ | 頂点のまわりの面について、初期の円盤の上での面積に比べ、画面に投影した面積が何倍に広がったかの逆数を掛ける。伸びた尾は暗くなる。投影で細く見えるところが明るくなりすぎないよう、掛ける値は 4 未満に抑える |
| ちぎれた面 | 三角形の 3 辺のうち、いちばん伸びた辺の伸び率を測る。隣の 3 つの面の伸び率の中央値の 3 倍を超えた面だけ描かない |

ちぎれた面の判定を、隣と比べる形にしているのは、尾全体が一様に伸びたところを消さないためです。伸び率そのものに上限を付けると、いちばん長く伸びた尾から消えていきます。

光は `rgba16float` のテクスチャに足し合わせてから、画面の色へ変換しています。

### つかんで投げる

小さいほうの銀河の円盤のあたりを押すと、銀河をつかめます。芯は、円盤のいちばん内側の 32 個の光の頂点の平均の位置です。つかめる範囲は、円盤の半径を画面へ投影した大きさか、60px の大きいほうです。

つかんでいる間は、毎歩、小さいほうの銀河のすべての点（質量点と光の頂点）に、同じ速度を足します。芯の目標の位置は、押したときの芯の位置に手の移動量を足したものです。芯は押した場所とのずれを保ったまま、手についてきます。足す速度は、今の芯の速度と次の歩で芯に掛かる重力の分を打ち消して、芯がその目標へ近づく速度にそろえる値です。「1 歩進める」で出てきた `bulkMotion` がこの速度です。

同じ銀河の点に同じ速度を足すので、補正そのものは点どうしの相対的な位置と速度を変えません。運んでいる間も円盤はまわり続け、それまでに伸びた尾も消えません。

| 操作 | 何をするか |
| --- | --- |
| つかんでいる間 | 芯と目標の差を、1 歩ごとに約半分ずつ縮める（時定数 12.5ms で指数的に近づく） |
| 離したとき | 直近 100ms の手の速さの 35% を芯の速度にする。実時間で 1 秒に 1.4 進む速さを上限にする |
| つかんでいないとき | 芯の動きをすこしずつ減速し、原点から半径 3.5 を出ると引き戻す。大きいほうの銀河には常に、小さいほうにはつかんでいない間に掛ける |

この減速と引き戻しは、銀河が遠くへ離れていき続けないようにするための、重力とは別の補助です。最初の自動のすれ違いのときから掛かっています。つかむときと同じく、銀河の全部の点に同じ速度の補正として足すので、円盤の中の動きは減速しません。

つかんでいる間に出る細い線は、今離したときの通り道の目安です。大きいほうの銀河を動かない 1 点とみなした近似で引いているので、実際の動きとはずれます。

小さいほうの銀河の外のドラッグでは、横の動きで見る向き、縦の動きで傾きを変え、真横まで回せます。大きいほうの銀河の上を押しても、見る向きが変わります。カメラは直交投影です。
